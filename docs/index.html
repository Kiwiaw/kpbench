The task

Every run is one way of choosing K keypoints per image. The benchmark asks how well a camera can be relocalised with those points. For each query frame the chosen points are matched to a small 3D map built from nearby keyframes (every 10th frame; a query uses the keyframes within 20 frames, usually 4), and the camera pose is solved from the matches. The map points are keyframe keypoints lifted to 3D with the ground-truth depth and pose, so the only thing that differs between runs is which points are kept.

A query fails when no pose is found, or the pose error is above the chosen threshold pair (dropdown below): 25 cm / 2°, 50 cm / 5° and 5 m / 10° are the standard pairs of the visual localisation benchmarks, 5 cm / 2° is a strict extra. Position error = distance between the estimated and the true camera centre; rotation error = angle between the estimated and the true rotation. The headline number of a run is its fail %: the share of failed queries. Lower is better.

Pose: OpenCV solvePnPRansac with the AP3P minimal solver, 3 px reprojection tolerance, 2000 iterations, at least 6 inliers, then Levenberg-Marquardt refinement on all inliers (the hloc recipe). The random generator is seeded per query, so a run can be reproduced exactly. Data: TartanAir (Hard), 640×480 frames with ground-truth depth and pose; the map points use the true depth, so the map is cleaner than any real map and failures are query-side failures.

One run = detector + picker + K + map

det
raco = RaCo, candidates ordered by its ranker score. sp = SuperPoint, ordered by its keypoint score. In both cases the 2000 strongest points of the image are the candidate pool and the descriptors are always SuperPoint's.
K
how many points are kept per image (20, 30, 50, 100, ...).
picker
the selection rule, applied to the candidate list.
score: the K strongest, no other condition.
sd: the K strongest that have depth (the usual baseline; points without depth cannot enter the map anyway).
cube0.5: the candidates with depth are binned into 0.5 m cubes in the camera frame; one point is taken from each cube in turn (strongest first), then the cubes are visited again until K points are chosen.
grid: the image is split into ⌈√K⌉ × ⌈√K⌉ cells; from a pool of the M strongest candidates with depth (M = 4K, between 80 and 400) the best point of every cell is taken, then the list is filled by rank.
grid10x8: 10 × 8 image cells, round robin, strongest first.
fps: farthest point sampling in the image on the same pool, where the gain of a point is its distance to the already chosen set times (1 − rank/M), so strong points are preferred. fps0: plain farthest point sampling.
map
same: the keyframes use the same picker and K as the query, so the map changes with the run. dense: every keyframe contributes its 300 strongest points with depth, the map is the same for all runs and only the query side changes. In both, a query is matched against the keyframes within 20 frames of it (2 to 5 keyframes), which acts as perfect image retrieval and includes future frames: the local-tracking setting.
ret5: same keyframe points as same, but the database is every keyframe of the flight and a query is matched against the 5 most similar ones by image retrieval (VLAD over the SuperPoint descriptors of the 300 strongest points, 64-word codebook learnt on the flight). No time information: the localisation setting, where retrieval can also fail.
matcher
nn: mutual nearest neighbour on the SuperPoint descriptors, no learned matcher. lg: LightGlue (SuperPoint weights) run between the query points and each keyframe's map points in turn; every query point keeps its highest-scoring match. LightGlue uses the point layout, so it can partly make up for a bad spread.
id
det_picker_K<K>_map_matcher[_tag], e.g. raco_grid_K100_same_nn or raco_cube0.5_K100_same_lg.

Columns

fail % (n) ±
share of failed queries at the chosen threshold; n = number of queries; ± = half width of a 95 % confidence interval from 1000 bootstrap resamples. Queries close in time see the same scene and fail together, so the bootstrap resamples blocks of 20 consecutive frames per flight, not single queries (a plain per-query bootstrap would give intervals 2 to 3 times too narrow). Two runs whose intervals overlap heavily are not distinguishable on this data. The sign test next to saves / breaks still counts queries as independent and is therefore optimistic.
AUC ≤25 cm
area under the curve "share of queries with position error ≤ x" for x from 0 to 25 cm, divided by 25, so 1 would mean every pose is exact. It rewards precise poses, not only passes.
median err
median position error in cm over the queries that passed at the threshold.
n_match
mean number of mutual matches per query. n_inl: mean number of RANSAC inliers.
rep1 / rep5 / rep10
repeatability: share of the kept points (with depth) that reappear 1, 5 or 10 frames later, i.e. the point projected with the true pose lands within 3 px of one of that frame's 300 strongest candidates with depth agreeing within 5 %.
saves / breaks / net / p
paired comparison with the BASELINE run on the same queries. saves = queries the baseline fails and this run passes; breaks = the opposite; net = saves − breaks; p = two-sided sign test on saves versus breaks (exact binomial, normal approximation above 500 pairs).
shared queries only
restricts every number to the queries that all shown runs have, so runs with different flight sets stay comparable. A "x/y flights" badge marks a run that covers fewer flights than the selection.
fail25 (index)
fail % at 25 cm over all queries of the run, as stored at export time; a quick sort key.

Per-query labels and bins

plane_frac
how flat the view is: the share of the 300 strongest SuperPoint points with depth that lie on one plane (RANSAC plane fit, 30 cm tolerance). Bins: ordinary < 0.55, mid 0.55–0.85, flat ≥ 0.85, very flat ≥ 0.95 (a subset of flat). Flat views are where spreading points should matter most.
coverage
share of the query image (8 px grid of points with depth) that at least one of its keyframes also sees, with depth agreeing within 10 %. Low coverage means the map hardly contains what the query looks at, and no picker can help.
med_depth
median depth of the query in metres (very close walls and very far scenes behave differently).
missing_depth
share of the 100 strongest points that have no depth (sky, out of range).
